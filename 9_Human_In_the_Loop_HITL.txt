HITL (HUMAN IN THE LOOP) IN LANGGRAPH
========================================================================

A. HITL Fundamentals
------------------------------------------------------------------------

	Definition:
		HITL (Human In The Loop) is an approach where a human actively
		participates at critical points in an AI workflow.

	Purpose:
		- Supervise AI decisions
		- Approve actions
		- Correct outputs
		- Guide workflow execution

	Simple Idea:
		Human checkpoint inside an AI pipeline.

	LangGraph Implementation:
		- interrupt()      -> Pauses graph execution
		- Command(resume)  -> Resumes graph execution

========================================================================

B. Why HITL Is Needed
------------------------------------------------------------------------

	Goal of Agentic AI:
		- Autonomy
		- Tasks should be completed automatically without human involvement.

	Problem:
		- LLMs are not perfect.

	Therefore:
		- Certain decisions still require human judgment.

========================================================================

C. Example: Travel Booking Agent
------------------------------------------------------------------------

	Workflow:
		1. Search flights
		2. Select flights
		3. Book ticket

	Important Observation:
		Before payment or booking confirmation, human approval
		should be requested.

	Reason:
		- Critical financial action is involved.

========================================================================

D. Two Main Reasons HITL Exists
------------------------------------------------------------------------

	1. Helping Agentic Systems

		Problems:
			- Ambiguity
			- Misinterpretation
			- Hallucination

		Example:
			"Book tickets for next Friday"

		Ambiguity:
			- This week's Friday?
			- Next week's Friday?

		Solution:
			- Ask human for clarification.

	--------------------------------------------------------------------

	2. Accountability

		Problem:
			- AI cannot be held accountable.

		Examples:
			- Email sending
			- Payments
			- Business actions

		Solution:
			- Human reviews final action.

========================================================================

E. Benefits of HITL
------------------------------------------------------------------------

	1. Better Accuracy
		Example:
			Invoice amount extraction.
			Human verifies amount before payment.

	2. Increased Safety
		Example:
			Deleting unused files.
			Human validates before deletion.

	3. Ethical Alignment
		Example:
			Customer support replies.
			Human can improve tone and empathy.

	4. Better User Experience
		Combines:
			- AI efficiency
			- Human judgment

========================================================================

F. Common HITL Patterns
------------------------------------------------------------------------

	1. Action Approval Pattern
		Purpose:
			Human approves important actions.
		Examples:
			- Payments
			- Important emails
			- File deletion

	2. Output Review Pattern
		Purpose:
			Human reviews generated output.
		Examples:
			- Blog drafts
			- Social media posts

	3. Ambiguity Clarification Pattern
		Purpose:
			Resolve unclear requests.
		Example:
			"Next Friday"

	4. Escalation Pattern
		Purpose:
			Transfer problem to a human agent.
		Example:
			Customer support escalation.

		Pause workflow, collect human decision,

I. What Happens During interrupt()?
------------------------------------------------------------------------

	Step 1: Workflow execution pauses.
	Step 2: Current state is saved.
	Step 3: Approval message is created.
	Step 4: Message is sent to frontend.
	Step 5: System waits for user decision.

========================================================================

J. What Happens During Resume?
------------------------------------------------------------------------

	Step 1: User responds.
	Step 2: Frontend sends Command().
	Step 3: LangGraph restores saved state.
	Step 4: Workflow resumes from interruption point.

========================================================================

L. input() vs interrupt()
------------------------------------------------------------------------

	input()
		- Blocks current process
		- Requires immediate response
		- No persistence
		- Simple Python functionality

	interrupt()
		- Pauses workflow
		- State can be saved
		- Can resume later
		- Enterprise-ready

========================================================================

M. What Is Stored During interrupt()?
------------------------------------------------------------------------

	LangGraph stores:
		- Current node
		- Thread ID
		- State variables
		- Workflow execution position

	Example:
		{
		    "question": "...",
		    "approved": "..."
		}

========================================================================

N. Role of Checkpointer
------------------------------------------------------------------------

	Why Required:
		Workflow pauses during HITL.

	Therefore:
		Current state must be saved.

	Checkpointer Stores:
		- State
		- Execution position
		- Workflow progress

========================================================================

O. Frontend Responsibilities
------------------------------------------------------------------------

	1. Receive interrupt message.
	2. Display approval request.
	3. Collect user response.
	4. Send Command() back.
	5. Resume workflow.

========================================================================

P. Backend Responsibilities
------------------------------------------------------------------------

	1. Trigger interrupt().
	2. Save state.
	3. Wait for response.
	4. Restore state.
	5. Continue execution.

========================================================================

Q. Key HITL Functions
------------------------------------------------------------------------

	interrupt()
		Purpose: Pause workflow.

	Command()
		Purpose: Resume workflow.

	Checkpointer
		Purpose: Store workflow state.

========================================================================

R. Can a Workflow Remain Paused for Days?
------------------------------------------------------------------------

	Answer: Yes.

	If using a persistent checkpointer such as PostgreSQL,
	the workflow can remain paused for:

		- Hours
		- Days
		- Weeks
		- Months

	and later resume.

========================================================================

S. Timeouts
------------------------------------------------------------------------

	How to Implement:

		Store:
			- created_at
			- status

		Example:
			Pending Approval

		If approval is not received within 24 hours:
			- Reject
			- Escalate
			- Notify another reviewer

			- Call APIs

========================================================================

U. Important Interview Scenario
------------------------------------------------------------------------

	Question:
		If the user closes the browser after interrupt(),
		how can the workflow continue later?

	Answer:
		The workflow state is saved using a persistent
		checkpointer such as PostgreSQL.

		When the user returns, LangGraph loads the saved
		state and resumes execution from the exact point
		where it was interrupted.

------------------------------------------------------------------------

	Question:
		If the user is not sitting in front of the laptop,
		how does HITL work?

	Answer:
		1. LangGraph saves workflow state.
		2. Workflow is paused.
		3. User can leave the application.
		4. User may return hours or days later.
		5. User approves or rejects.
		6. Graph resumes using Command(resume).

	Suitable For:
		- Banking approval flows
		- Compliance reviews
		- Manager approvals
		- Enterprise workflows

------------------------------------------------------------------------

	1. HITL = Human In The Loop.
	2. HITL introduces human judgment into AI workflows.
	3. Major reasons:
		- Better decision making
		- Accountability
	4. Main benefits:
		- Accuracy
		- Safety
		- Ethical alignment
		- Better UX
	5. Common patterns:
		- Action Approval
		- Output Review
		- Ambiguity Clarification
		- Escalation
	6. LangGraph implements HITL using:
		- interrupt()
		- Command()
